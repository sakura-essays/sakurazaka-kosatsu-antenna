## 実装

- `scripts/collect.py`: 創作ラベル・脚本・伏せ字会話の検出改善。妄ツイ文化への批評は一律除外せず確認待ちに置く。新規記事で正規化後40文字未満のRSS本文は公開せず保留（既存公開・確認済み記事を除く）。文字数は十分条件ではない。混在書き手は引き続き全件個別承認が必要。
- `scripts/review.py`: 本文確認済み記事の一括検証・個別承認・過去記事のメタデータ補完。ブロック、明示保留／除外、所有書き手、公開日、カテゴリー、重複を確認。全件検証後に保存。本文は保存しない。
- `scripts/admin.py`: 承認／保留時に既存のグループ・分類・確認記録を消さない。
- `scripts/check_release.py` と `.github/workflows/update.yml`: 前回公開URLが明示的な管理操作なしに消える場合、ビルド／本番公開の前に停止する。
- `config/sources.json`, `config/overrides.json`, `config/manual_articles.json`: 書き手3件・個別承認8件・未取得時に備えた手動メタデータ4件を追加。既存ブロック・手動設定を維持。
- `tests/test_pipeline.py`, `tests/test_article_reviews.py`, `tests/test_release_guard.py`: 安全策、選択収集、承認記録保持、公開減少停止の回帰テスト。
- `config/rules.json`、UI、検索、色、ピックアップ等は変更しない。

## 操作

候補メタデータ（除外を含む）を確認する：

```sh
python scripts/review.py > /tmp/article-candidates.json
```

公開記事本文を読んでから、次のようなJSON配列を作る。タイトル、書き手、公開日、グループ、カテゴリー、確認理由を照合する。

```json
[{
  "url": "https://note.com/example/n/EXAMPLE",
  "author_id": "example",
  "title": "元記事の正確なタイトル",
  "published_at": "2025-01-02",
  "groups": ["乃木坂46"],
  "categories": ["グループ運営・アイドル論"],
  "body_checked": true,
  "evidence_url": "https://note.com/example/n/EXAMPLE",
  "reason": "実際の制度への批評であることを公開本文で確認"
}]
```

```sh
python scripts/review.py --apply /tmp/reviews.json --dry-run
python scripts/review.py --apply /tmp/reviews.json
python scripts/collect.py --source-id example
python scripts/check_release.py
python scripts/build.py --public
```

書き手は別途sourcesに `enabled: true`, `article_policy: review_required` で登録する。承認はその記事だけに効く。
承認時のタイトルと収集時のタイトルが変わった場合、再確認待ちに戻す。既存の旧形式の手動承認は維持する。
通常の定期収集は従来どおり引数なし。選択収集では他の書き手の保存記事と以前の取得結果を維持する。

## 調査の範囲・制限

- noteのrobots.txtを確認し、公開プロフィール・記事・RSSとタグ画面だけを利用。禁止されたAPI、検索エンドポイント、アーカイブ、コメント一覧を取得していない。
- 櫻坂46・乃木坂46・日向坂46・青葉坂46・坂道の人気と新着、計10画面の初期表示を取得。新着の実際のリンクは `/tag/<tag>?mode=new` であり、旧形式 `?f=new` だけでは新着を確認したことにならないため実リンクを追った。
- 検索による候補補完も実施。タグ全ページの網羅調査・全候補の本文精読・全178人の全公開記事確認は未実施。既存全記事の状態差分は確認した。
- ゆうまっち等、今回実活動の批評本文を確認できなかった候補は登録していない。
- 有料部分や不足本文から内容を推測して承認しない。久世 遊一の歌詞考察候補は公開導入だけでは結論・創作との比重を確認できないため保留を維持。
- 混在書き手の今後の考察も自動で全文審査する方式ではない。RSSで候補を蓄積し、人が本文を確認して個別承認する。本文変更を常時検知する仕組みはなく、タイトル変更のみ検知する。
- 正解率・再現率を全体の数値として保証するものではない。7人129件の比較と具体的な本文確認例に基づく限定的な検証。
- 依存ライブラリ・画像・本文データを追加していない。UIの読み込み処理は変更していない。
