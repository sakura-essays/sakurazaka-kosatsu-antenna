# 坂道考察アンテナ

実在するnote・はてなブログのRSSを使う、個人の考察・批評・感想へのリンク集です。
公開先：https://github.com/sakura-essays/sakurazaka-kosatsu-antenna

サイト： https://sakura-essays.github.io/sakurazaka-kosatsu-antenna/

現在の公開・更新状況はリポジトリのActionsとサイトの取得状況を確認してください。

## まず画面を見る

`dist/index.html` をダブルクリックすると、インストールなしで収集済み記事の検索・絞り込みを使えます。
書き手別ページも `dist/authors/` にあります。データはファイルに同梱しており、閲覧のたびに筆者のサイトにアクセスしません。

## 実装済み

- RSS/Atomによる自動取得と、確認済み過去記事のメタデータ登録。本文ページのスクレイピングや非公開APIは使いません。
- URL正規化・重複排除・過去記事の蓄積・公開日の保持。
- 乃木坂・櫻坂／欅坂・日向坂のグループ別判定、メンバー名、番組名、楽曲名、RSS配信文による選別。
- 曖昧な記事の確認待ち、非関連記事の除外、管理者による上書き。
- グループ別タブ（全体・乃木坂46・櫻坂46・日向坂46・青葉坂46）、指定カテゴリー（従来の8種に2番組・「制作者・クリエイター論」を追加）。複数所属、タイトル・筆者・メンバー・楽曲・媒体・日付検索。
- 新着順、古い順、書き手を交互にする表示、30件ずつの追加表示。新着を隠さない任意操作の「過去記事を1本引く」機能：30日以上前の公開記事から書き手を先に抽選して記事を選びます（厳選・AI採点ではなく無作為抽選）。検索・詳細フィルター中は非表示、グループ・カテゴリーは尊重し、ピックアップ登録済みの6本は別枠として除きます。
- フッターに1リンクだけ置いた「楽曲別索引」(`songs.html`)。公開記事のタイトルで楽曲名を確認できるものを、グループ・楽曲ごとに静的HTMLで表示します。元記事タイトル、書き手、リンクのみで、スキ数や品質順位は扱いません。サイトマップにも追加し、通常の検索画面やフィルターは変更しません。曲名がタイトルにない記事や辞書未登録曲は索引から漏れることがあります。
- 書き手一覧と、個別URLを持つ書き手ページ。書き手一覧は各ページ読み込み時にFisher–Yates方式でランダム化し、ボタンで再抽選可能。画面を移動して戻っただけでは順番を変えません。「書き手を探す」には書き手名・ブログ名・公開ユーザーID・扱うグループ名でリアルタイムに絞り込める検索欄（該当人数・検索クリア付き）を備え、検索中もランダムな並び順を維持します。主なテーマは分類件数の自動集計。
- 反応の大小とは別に読み応えがある考察を紹介する、順位・採点非公開のピックアップ欄（選定記事がある場合のみ表示）。
- PC・スマートフォン向け表示。広告、画像転載、トラッキングなし。
- 取得状況表示、エラーログ、失敗時のデータ保持。
- 掲載停止URL・筆者のブロックと再収集防止。
- GitHubの画面から候補追加・承認・停止できるActions設定。
- 掲載取り下げ・訂正・推薦のGitHub Issueフォーム。
- 6時間ごとの収集・蓄積・Pages公開ワークフロー。

## 公開設定と連絡窓口

公開リポジトリは `sakura-essays/sakurazaka-kosatsu-antenna`、既定ブランチは `main` です。
PagesのSourceはGitHub Actionsを使用します。未有効の場合はSettings → Pages → SourceでGitHub Actionsを選んでください。

更新予定は日本時間03:17 / 09:17 / 15:17 / 21:17です。GitHub側の都合で遅延・欠落する場合があります。

掲載取り下げは [専用Issueフォーム](https://github.com/sakura-essays/sakurazaka-kosatsu-antenna/issues/new?template=removal.yml) で受け付けます。GitHubアカウントが必要で、投稿は公開されます。個人情報を投稿しないようサイトとフォームに明記しています。個人メールアドレスは掲載していません。

将来のフォーム変更は `config/settings.json` の `contact_url` を変更すると、サイト内の連絡先も更新されます。その際は `web/contact.html` の受付条件も新しい窓口に合わせて変更してください。

公開リポジトリのstateには公開記事のメタデータだけを保存します。私的メモ、連絡先、APIキーは置かないでください。

## 日々の操作は不要。必要なときだけ管理します

- **書き手の候補追加**：Actionsの `Run workflow` で `add_candidate` を選び、`target_url` にブログのトップURLを入力。まだサイトには掲載されません。
- **書き手を承認**：`state/candidate-書き手ID.json` の見出しと元記事・ブログの利用条件を確認し、`approve_source` と `source_id` を指定して実行。
- **筆者の掲載を停止**：`remove_source` と `source_id` を指定。
- **記事を取り下げ**：`remove_article` と記事URLを指定。次の取得でも復活しません。
- **確認待ちの記事を載せる**：`state/review.json` を確認し、`approve_article` と記事URLを指定。公開日が確認できない記事は日時確認が先です。
- **記事を保留**：`hold_article` と記事URLを指定。
- **カテゴリーの訂正**：`config/overrides.json` の `articles` に、対象URLと `categories` 配列を設定します。8カテゴリーの名称をそのまま使います。
- **失敗の確認**：Actionsの赤い実行を開く。`state/status.json` に媒体ごとの原因が残ります。サイトの「このサイトについて」にも取得失敗を表示します。
- **月1回程度**：掲載取り下げ・候補・誤分類を確認。Actionsの停止がないか確認してください。GitHubは公開リポジトリに60日間活動がないと定期実行を停止する条件があります。

追加URLからRSSを推定する管理機能はnote・はてなブログを対象にしています。WordPress等もRSS/Atomパーサーで扱えますが、利用条件とフィードURLを個別確認して `config/sources.json` へ追加する必要があります。

## 青葉坂46の考察・批評の収集（2026年11月）

2026年8月18日の坂道グループ公式発表に沿って、約1年間の活動後に3グループへ配属される青葉坂46も独立したグループとして扱います。色分けは緑系を使用します。見出し内の「青葉坂46」「青葉坂」「aobazaka46」等から自動分類し、既存3グループのメンバーやグループが同時に見出しに登場する考察は複数グループに掲載できます。青葉坂の固有メンバーや専用楽曲は確認できた時点で追加する方針で、他グループの坂道選抜「Audition」を青葉坂の専用楽曲とは扱いません。

RSS配信範囲外になった既存記事も、収集済みで見出しから青葉坂への関係が明確な場合は再分類します。記事の公開・保留・除外や管理者による分類指定は勝手に変更しません。対象となるブログやnoteが未登録の場合、従来通り書き手の候補登録・確認が必要で、新規書き手を自動発掘する機能はありません。

## 制作者・クリエイター論の収集

坂道の振付・ステージング・MV監督・衣装・作詞作曲・運営などの制作に携わる人やチームへの考察・批評を扱います。TAKAHIRO、INFINITY所属の振付師・ダンサー（川村茜、米山美優、北畑向夏花ほか）、CRE8BOY、Seishiroなどを対象に追加しました。タイトルに批評・分析の手掛かりがあり、坂道との関係が確認できるものに限ります。単なる出演告知や振付担当のクレジットではこのカテゴリーに入りません。

旧「秋元康・制作者論」は収集時と公開ビルド時に新しい名称へ読み替えます。既存記事のURL・公開日・掲載判断は維持します。新しい書き手の自動発掘は行わず、RSS配信範囲外の過去記事は個別確認が必要です。


「制作者・クリエイター論」は単に記事本文やRSS抜粋に名前が出るだけでは付けません。タイトルで秋元康本人への論評・作詞観・プロデュース論が確認できる記事と、坂道／AKB48との関係が明確な制作スタッフ（振付・衣装・運営など）についての批評を対象とします。AKB48やその他アイドルを論じた記事でも、秋元康の制作活動そのものが中心なら「すべて」とカテゴリー内に掲載し、乃木坂・櫻坂・日向坂のタブには無理に分類しません。単なる作詞クレジット、ニュース・転載、日常の雑記、創作小説は対象外です。

検出はRSS見出しを中心とした保守的な自動判定です。曖昧な記事は個別承認が必要で、新しく登録した横断的なアイドル考察者には `article_policy: review_required` を設定して誤収集を防ぎます。通過儀礼さんの「晩期秋元康」と深山1234の「アイドルの制作者たち」は `config/magazine_feeds.json` の既存の仕組みで過去記事も補完します。マガジンに含まれるだけで無関係の記事を自動掲載せず、制作者への考察と確認できるものだけを扱います。記事本文は保存しません。

## 創作混在の書き手からの考察・感想の収集

`article_policy: review_required` の書き手は、一律に全記事を保留するのではなく、記事単位で判定します。見出しに「考察」「感想」「批評」「レビュー」「分析」「解説」「論評」「振り返り」「レポート」「参戦記」などがあり、見出しから対象グループ・メンバー・楽曲、または対象の制作者への言及が確認できる記事は、通常の関連性判定と創作除外を通過した場合に限り自動公開の候補となります。RSSの本文抜粋が短すぎる新規記事は従来どおり保留します。

妄ツイ・夢小説等の明示や創作の手掛かりがある記事、記事のジャンルが曖昧な場合は保留または除外し、管理者の個別判定を優先します。普段の投稿ジャンルによって考察・感想を一律に除外せず、逆にメンバー名があるだけで創作を公開もしません。書き方の巧拙、考察の深さ、独創性、スキ数などで通常の記事を採点・選別する機能はありません。読み応えによる編集判断はピックアップ欄だけに限定します。

## ピックアップの管理

`config/pickups.json` に、管理者が本文を読んで評価し、反応が大きくないことも確認した公開済み記事だけを登録します。

```json
[
  {"url": "https://note.com/<account>/n/<article-id>", "note": "紹介したい具体的な理由（160字以内）"}
]
```

これは入力形式の例で、架空URLを登録してはいけません。現時点の初期設定は空のため、ピックアップ欄は表示されません。登録があれば最大6件をランダム順に表示します（ランキングではありません）。記事は既存の公開済みURLと照合し、非公開化・掲載停止した記事は表示しません。グループ別タブに対応し、検索・書き手等の絞り込み中はピックアップを非表示にします。

noteのスキ数や閲覧数はRSSに含まれないため、反応の少なさは管理者が確認する必要があります。AIによる自動採点やリアルタイム反応取得はまだ実装していません。数値評価や非公開の評価メモを公開リポジトリのconfig・stateやActionsログに保存しないでください。公開するのは選定URLと短い紹介文だけです。

## 過去記事について

最初から全記事を集める機能ではありません。noteは通常最新25件、はてなブログは最新30件をRSS配信します。初回はその範囲、以後は取得した記事を蓄積します。更新が止まっているブログのRSSには数年前の記事が残っているため、初期データにも2020年の記事があります。

RSSを出なくなった記事は消しません。RSS範囲外の一部の過去記事は、管理者がタイトル・URL・公開日を確認したものに限り `config/manual_articles.json` で登録できます。本文や画像は保存せず、重複時はRSSを優先し、元の公開日で並べます。手動登録した公開日時は日付単位の情報です。元記事の削除や公開範囲変更を全件定期巡回する機能は未実装で、連絡を受けた場合に掲載停止できます。

## 新しい書き手の発掘

当面は月1回、検索エンジンで「櫻坂46 考察 note」「櫻坂46 感想 はてなブログ」「欅坂46 歌詞 考察」などを検索し、更新時期を変えて確認します。noteの公開マガジン、はてなブログの公開グループ、推薦フォームも入口にできます。検索結果ページの自動スクレイピングは行いません。

## 開発・検証

Python 3.12とNode.jsを使用して検証しました。Python側は標準ライブラリのみで動作します。

```sh
python -m unittest discover -s tests -v
python scripts/collect.py
python scripts/build.py
```

一般公開向けの設定検証を含むビルド：

```sh
python scripts/build.py --public
```

`collect.py` は全フィード成功時0、一部・全部失敗時2を返します。失敗した媒体の既存記事は保持し、ワークフローは正常に取得できた分とエラー状態を公開したうえで失敗を報告します。画像・本文は `state` にも `dist` にも保存しません。RSS原本は通常運用ではメモリ内で処理して破棄します。

HTTPS、URL検査、外部サイトへのリダイレクト検査、robots.txt確認、1秒以上の取得間隔、25秒タイムアウト、4MB上限を設けています。ETag/Last-Modifiedが返された場合は次回に条件付き取得します。429/5xxを無限再試行せず、次回の定期実行を待ちます。

## 未実装・判断の限界

- クリックランキング：未計測の数値は作りません。初期版では実装価値より管理負担が大きいと判断しました。
- 全過去記事の自動遡及取得：RSSの範囲外を大量に取得しません。
- 新規書き手の無人発見：無料かつ継続利用できる検索手段が未確保。
- WordPress・Amebaの実データ登録：今回はnote・はてな優先。パーサー対応と媒体ごとの動作確認は別です。
- AIによる全文の意味理解：有料APIを使わず、配信範囲の語句判定です。日常・広告・自己紹介の混入や関連投稿の取りこぼしは残ります。
- 筆者が完全に自力で書いたか、内容が事実か、優れた考察かをRSSだけで判定することはできません。掲載は内容の正確性や制作方法の保証ではありません。
- 自動分類されたメンバー・楽曲は「本文全体の中心人物・主題」を保証しません。辞書は一部の楽曲に限り、網羅的な公式データベースではありません。
